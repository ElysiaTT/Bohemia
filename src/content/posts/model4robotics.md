# Claude Plays Robotics：当 LLM 开始控制机器人

最近读了 Anthropic 发布的 [Claude Plays Robotics](https://www.anthropic.com/research/claude-plays-robotics)。这篇工作提出了一个很有意思的问题：

**一个没有经过专门机器人训练的通用大模型，究竟能在多大程度上控制真实的物理系统？**

过去讨论机器人的智能水平，我们习惯看 VLA 在 LIBERO、RoboTwin 等 Benchmark 上的任务成功率。但 Anthropic 换了一个角度：不直接训练新的机器人基础模型，而是让 Claude、GPT、Gemini 等通用模型通过不同的控制接口与机器人交互。

最终的结论比单纯的模型排行榜更值得思考：

**LLM 的机器人能力不仅取决于模型本身，还高度依赖它能调用什么工具、拥有多大的控制权限，以及能否利用执行反馈修正自己的行为。**

## 01. Embody：如何评测 LLM 的机器人能力？

Anthropic 构建了一套名为 Embody 的 Benchmark，覆盖三类任务：

- **Classic Control**：倒立摆、Hopper 和新设计的 TwinFlipper，主要考察动力学理解与低维控制。
- **Locomotion**：使用 Unitree Go2 四足机器人和 G1 人形机器人，测试站立、平衡、行走与导航。
- **Manipulation**：使用 Franka Panda 机械臂，在 LIBERO 及新增场景中完成触碰、抓取和放置等任务。

大部分实验在 MuJoCo 仿真中完成，论文还包含少量真实 Go2 机器人的探索性实验。

但我觉得更有意思的不是任务本身，而是他们为相同模型提供的四种不同控制接口。

| Interface | LLM 负责什么 |
|---|---|
| Direct Control | 直接输出力矩、力或末端运动命令 |
| Programmatic Control | 编写 Python 控制器，将状态映射为动作 |
| Policy Control | 调用、监督已有的机器人策略 |
| RL Supervision | 设计奖励、网络与训练计划，通过 PPO 训练策略 |

这里实际上对应着四种不同的机器人智能实现方式。

Direct Control 要求 LLM 自己解决底层控制问题，而 Policy Control 将低层执行交给已经训练好的 Policy。

换句话说，**研究者改变的并不只是模型，而是模型与物理世界之间的接口。**

论文的综合分数中，Mythos Preview 达到 0.389，Opus 4.6 达到 0.351，GPT-5.4 为 0.251。需要注意，这些是跨任务归一化后的综合指标，并不代表机器人任务成功率分别为 38.9%、35.1% 和 25.1%。

不同模型在不同控制接口上的排名也并不一致。

这让我觉得，单独用一个综合分数评价所谓的 Embodied Intelligence，其实会掩盖很多重要的能力差异。

## 02. LLM 不擅长直接控制，但很擅长编写控制器

在经典控制任务中，Anthropic 发现一个现象：

**让 LLM 编写 Python Controller，通常比让它逐步输出底层动作更有效。**

原因并不难理解。

假设机器人需要维持倒立摆平衡。Direct Control 要求 LLM 在每次观测后输出一个新的控制动作，而倒立摆的稳定性取决于连续、及时的反馈。

但对于 Programmatic Control，LLM 可以直接编写一个反馈控制器：

`observation → controller(obs) → action`

之后，这个控制器就可以在仿真循环中持续运行，不需要每一步重新调用 LLM。

这相当于将 LLM 从实时控制器转变为控制器的设计者。

而且，论文发现较新模型在经典控制任务上的优势，并不完全来自更好的首次尝试。

很多时候，模型第一次编写的控制器仍然表现很差；真正的提升来自它观察失败结果后，能够修改控制逻辑并在后续尝试中取得更好的表现。

这让我联想到 Agent 的一个重要能力：

**不是第一次生成的策略有多好，而是能不能通过环境反馈持续修正错误。**

不过，这种改进目前主要发生在短期交互中，并不能直接等同于长期技能学习。

## 03. 让 LLM 自动训练 PPO，结果反而没有想象中好

Anthropic 还做了一个很有意思的实验：让 LLM 从零训练强化学习策略。

模型可以设计 Reward Function、Policy Network 和训练计划，再调用 PPO 训练工具。

实验使用 GPU 并行 MuJoCo 环境，默认最多提供 32 个并行环境。经典控制任务的单次实验预算为 1.5 小时，Go2 和 G1 则为 4 小时。

从 Agent 的角度来看，这已经是一个自动化 RL 工作流：

**设计实验 → 训练策略 → 获取评测结果 → 调整训练方案 → 部署策略。**

但结果却有些反直觉。

在经典控制任务中，几乎所有模型训练出的 RL Policy，都不如它们直接编写的 Python Controller。

一个例外是 TwinFlipper。在这项新设计的弹球控制任务中，GPT-5.4 是唯一能持续训练出有竞争力策略的模型。

我觉得这里不能简单得出「LLM 不适合 RL」的结论。

直接编写控制器与训练 PPO 所需要解决的问题不同。

前者可以利用模型已有的物理和编程知识，直接构造反馈控制规律；后者则需要设计合理的奖励、选择策略网络、管理训练过程，还必须在有限采样预算内找到有效策略。

因此，LLM 自动训练 RL 的能力，实际上同时受到 Reward Design、Experiment Planning 和 Sample Efficiency 等因素影响。

这也提醒我：以后如果研究 Agent 自动生成机器人策略，不能只展示最终训练成功的例子，还应该比较它与固定训练配置、人工奖励函数以及等预算超参数搜索之间的差异。

否则很难证明收益究竟来自 Agent 的推理能力，还是来自更多次试验。

## 04. 最值得关注的部分：LLM + VLA 不一定比 VLA 更强

这部分是我阅读整篇文章时最感兴趣的实验。

Anthropic 在 LIBERO 场景中引入了预训练 VLA——MolmoAct。

VLA 根据机器人观测和任务指令提出动作，而 LLM 负责监督这些动作，决定接受、修改或替换。

整个过程可以理解为：

**Observation → VLA Proposed Action → LLM Supervisor → Robot Execution → Feedback**

乍一看，这似乎是一个很合理的架构。

VLA 擅长低层操作，LLM 擅长理解任务、推理和规划。两者结合之后，理论上应该比单独运行 VLA 更强。

但实验结果并不完全支持这个直觉。

在标准 LIBERO-40 任务上，所有参与评测的 LLM Supervisor 都使 MolmoAct 的原始性能下降。

这意味着很多 LLM 虽然能够理解任务，却不一定能正确判断 VLA 什么时候需要帮助。

更有意思的是，综合表现最强的 Mythos Preview，在这部分实验中反而不如 Opus 4.5 和 Opus 4.6。

原因是它过于相信自己的判断，频繁修改原本正确的 VLA 动作。

**一个推理能力更强的 Supervisor，并不一定是更可靠的 Supervisor。**

但在三个 MolmoAct 原本无法独立完成的 Novel Tasks 上，情况发生了变化。

部分较新模型开始能够识别 VLA 的错误提议，并通过干预带来额外收益。Mythos Preview 还成功完成了其中一部分新任务。

所以这里其实存在一个明显的矛盾：

当 VLA 本身表现可靠时，LLM 干预可能造成额外损失；但当 VLA 面对分布外任务时，LLM 又可能弥补其能力不足。

这让我想到一个更值得研究的问题：

**什么时候应该相信基础策略，什么时候才应该进行干预？**

相比让 LLM 无条件接管 VLA，我觉得选择性干预（Selective Intervention）可能是更有价值的方向。

一个理想的 Supervisor 不应该只会发现错误，还应该知道自己的修正是否真的比原策略更好。

## 05. 机器人当前的瓶颈，可能不只是视觉理解

另一个让我意外的实验是对视觉辅助工具的消融。

研究者为模型提供深度图、语义分割、第三人称视角、指向工具和方向信息。

结果并不是视觉信息越丰富，表现就越好。

在部分操作任务中，增加深度图或语义分割几乎没有带来提升；而一个简单的交互式 Cursor，却能够明显提高机械臂操作成功率。

例如在 10 个 LIBERO 任务构成的子集上，Mythos Preview 使用 Cursor 后，成功率从 6% 提升到 32%。

类似地，在四足机器人导航任务中，提供方向角的 Compass 也带来了明显收益。

这让我想到，当前模型的瓶颈可能不仅是「能否看懂图像」，还包括：

**能否把视觉信息转换为准确的空间状态，并在执行过程中持续维护这个状态。**

模型可以识别前方的物体，却未必准确知道自己距离物体多远；可以理解目标在哪里，却可能在执行数次转向后丢失自己的朝向。

论文还发现，更长的推理时间并不稳定地改善机器人任务表现。有些场景下，更高的推理预算反而会导致过度复杂化，影响即时控制效果。

因此，在机器人任务中，更多视觉 Token、更长的 Chain of Thought 并不必然等价于更好的闭环控制。

有时候，一个准确的方向角、距离查询或执行状态反馈，比额外的推理更有效。

## 06. 从仿真成绩到真实机器人，还有多远？

虽然论文展示了明显的代际进步，但我觉得仍然需要注意评测设置。

尤其是 Direct Control。

为了避免 LLM 的 API 延迟主导实验结果，Anthropic 会在部分直接控制实验中暂停 MuJoCo 仿真，等待模型生成下一步动作。

这相当于在假设模型能够及时输出动作的情况下，评估它潜在的物理推理与控制能力。

但真实机器人不会在等待 API 的过程中暂停物理世界。

例如四足机器人需要持续执行高频控制。如果一次 LLM 推理耗费数秒甚至数十秒，那么无论动作规划多么合理，都不可能直接作为底层实时控制器使用。

此外，Anthropic 的实体机器人实验主要是对 Go2 的探索性测试，而不是与仿真同等规模、严格对齐的真机 Benchmark。

所以我更愿意将这篇工作理解为：

**它展示了通用大模型具备怎样的机器人能力潜力，但没有证明这些模型已经能够可靠地直接部署为真实机器人的底层策略。**

## 07. 我的一些研究思考

联系之前接触 π0.5 真实机器人部署的经历，我对这篇文章最大的感触是：机器人能力不能只从模型的动作预测质量来判断。

一个 VLA 即使能够在离线数据上输出看似合理的动作，也可能在真实闭环执行中因为状态偏差、控制延迟或 Action Chunk 边界问题逐渐失稳。

这也是为什么我对 Anthropic 的 VLA Supervisor 实验格外感兴趣。

如果将它扩展为一个更完整的 Robot Agent Harness，我觉得可以将研究问题定义为：

**Can an agent improve a frozen robot policy through selective, feedback-driven intervention?**

首先冻结一个已有 VLA，让它独立执行标准任务和具有执行偏差的长尾任务。

然后引入一个 Supervisor，根据当前观测、策略提议的动作以及历史执行反馈，判断是否需要干预。

但这里最重要的并不是让 Supervisor 尽可能多地纠错，而是验证干预的净收益。

实验至少应该区分四种情况：VLA 单独执行、VLA 加入等预算重试、VLA 加入无条件 Supervisor，以及 VLA 加入选择性干预机制。

除了最终任务成功率，还需要观察错误干预率、漏检率、恢复成功率，以及每次干预增加的时间和计算成本。

否则，我们可能只是给原本已经不错的 VLA 增加了一个新的错误来源。

另一个值得探索的问题是，Agent 能否将一次失败中得到的纠错经验转化为可复用的技能，而不只是修改当前 Episode 的下一步动作。

这就从简单的在线纠错，进一步走向了部署期适应和跨任务技能复用。

当然，这些属于基于论文结果延伸出的研究设想，并不是 Anthropic 已经验证的结论。

## 08. 结语

读完这篇文章，我最大的收获并不是哪个模型在 Embody Benchmark 上获得了最高分，而是重新思考了 LLM 在机器人系统中应该扮演什么角色。

它未必需要直接输出每一个关节的动作，也未必需要替代已有的 VLA。

相比之下，利用已有策略、诊断执行失败、设计控制程序、生成训练数据，并在适当的时候修正机器人行为，可能是通用大模型更有价值的切入点。

而这里真正困难的地方，不是让模型学会干预，而是让它学会**什么时候不应该干预**。

**A good robot agent should not only know how to act, but also when to trust the policy it already has.**
