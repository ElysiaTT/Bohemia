搭建个人博客时，最容易遇到的问题不是工具太少，而是选择太多。框架、数据库、内容管理系统，每一样似乎都有值得使用的理由。

可以先换一个问题：这个博客真正需要做什么？如果主要需求是发布文章、组织内容，并且让别人舒适地阅读，那么静态网站就是很好的起点。

## 先让内容独立存在

Markdown 把文章保存在普通文本文件里。它可以被编辑器打开，被 Git 记录，也方便迁移。

一篇文章的结构很简单：上方是标题、日期等信息，下方是正文。

```markdown
---
title: "今天学到的一件小事"
description: "把一个问题讲清楚。"
date: 2026-11-10
category: "技术"
tags: ["学习笔记"]
---

## 问题从哪里开始

写下你的观察和思考。
```

这样，文章的生命就不必依附于某个在线编辑器。

## 在构建时完成大部分工作

Astro 可以在构建阶段读取文章、生成页面。访问者拿到的是已经生成的 HTML，而不是等一整套客户端应用启动后才能看到正文。

博客中只有少量行为需要 JavaScript：切换主题、筛选分类、搜索文章。阅读本身可以保持简单。

| 需求 | 在这个小站中的实现 |
| --- | --- |
| 写文章 | Markdown 文件 |
| 发布页面 | Astro 静态构建 |
| 搜索内容 | 构建时生成的 JSON 索引 |
| 获取更新 | RSS 订阅 |
| 自动发布 | GitHub Actions |

## 把发布变成一次提交

GitHub Pages 适合托管构建后的静态文件。配合 Actions，提交新文章后，就可以触发检查、构建与部署。

需要留意网站路径。个人主页仓库通常使用根路径，普通项目仓库则会带有仓库名。在生成内部链接和图片地址时，两种情况都应当被考虑。

```sh
npm install
npm run dev

# 发布前，检查类型并生成静态文件
npm run check
npm run build
```

## 留一点克制

技术可以不断增加，但维护成本也会跟着增长。先把阅读、写作、发布这条路径打通，再根据真实需要增加能力。

一个小而美的博客，不一定拥有最多功能。它只是让你更愿意写，让别人更愿意读。
